# legacy_reference\

重构前的单体程序 `ReagentMGS.py`，**归档在这里只作为测试对照基准**。

它不是程序的一部分 —— 正式代码在 `app/` 下，`build.spec` 也不会打包这个目录。

## 谁在用

| 测试 | 用途 |
|---|---|
| [test_gs1_parity.py](../test_gs1_parity.py) | 把旧的 `GS1Parser` 与新的 `app.core.gs1` 放在同一语料上**逐键比对** |
| [test_legacy_upgrade.py](../test_legacy_upgrade.py) | 用旧的 `ReagentDatabase` **真的写出一个老库**，再让新代码打开，验证升级路径 |

这两个是整套测试里最有说服力的一部分：它们验证的不是"新代码自洽"，而是
**"新代码与旧代码在真实输入上行为一致"**。删掉这份文件，它们就没法跑了。

## 顺带说明

`app/core/` 与 `app/handlers/` 下的模块注释里，有十几处写着
「照搬自 ReagentMGS.py 第 N 行」之类的出处。那些行号指的就是**这份文件**，
用来核对新实现有没有改动旧行为。

## 它不是"旧版本备份"

真要找重构前的完整版本，看 git 历史。这份之所以留在工作区，唯一的原因是
上面那两个测试需要一个**可导入的旧实现**。
